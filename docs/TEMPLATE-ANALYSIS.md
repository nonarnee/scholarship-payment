# 템플릿·샘플 실측 분석 (1개월분 마스킹 샘플)

> 근거: `samples/`의 마스킹 xlsx 2개를 Python 표준 라이브러리(zipfile + XML)로 읽기 전용 분석한 결과.
> openpyxl/Excel 실행 검증은 아직 하지 않았다. 개인정보 값은 이 문서에 옮기지 않았다(구조·형식·일치 여부만 기록).
> `docs/FILE-STRUCTURE.md`와 다른 점은 **§7 차이 보고**에 모았다. 문서를 임의로 고치지 않았다.

## 1. 입력 샘플 (비공개 파일)

| 항목 | 실측 |
|---|---|
| 시트 | `월별지급승인` 1개 |
| 사용 범위 | `A1:X48`, 병합 22개 |
| 헤더 | 1~2행(2단). 병합: A~N, V~X는 `행1:행2` 세로 병합, `O1:Q1`(재단 장학금), `R1:S1`(대학 자체 장학금), `T1:U1`(계좌번호) |
| 데이터 | 3~47행, **45명**, 중간 공란 없음 |

## 2. 출력 샘플 (비공개 파일)

| 시트 | 범위 | 병합 | 수식 | 비고 |
|---|---|---:|---:|---|
| `지급대상자명단(9월)` | A1:Q50 | 14 | 90 | 탭 색 노랑 |
| `WINS` | A1:I46 | 0 | 135 | |
| `wins 업로드 결과(2.9)` | A1:V45 | 0 | 0 | **헤더 22개만 존재, 데이터 행 없음** |
| `WRIS` | A1:J46 | 0 | 180 | |
| `은행코드` | A1:D79 | 0 | 0 | pageSetup 없음 |

패키지 구성: `calcChain.xml`, `printerSettings1~4.bin`, 공유 수식(shared formula), 조건부 서식 있음. 차트·피벗·표(Table)·데이터 유효성·시트 보호는 없음.

### 2.1 `지급대상자명단(9월)`
- `A1:Q1` 병합 제목. 형식: `{학년도} {학기} 대학생 청소년교육지원장학금 ({연}년 {월}월분) 지급 명단` (문자열 하나).
- `Q2`: `*기준 : YYYY.MM.DD` 문자열. 샘플 값은 입력 파일 작성일이 아니라 **다음 달 7일**로 보인다(파일명 날짜 접미사와 일치). 규칙 미확인.
- 헤더 3~4행: `A~K`, `Q`는 `행3:행4` 세로 병합, `M3:P3`("계좌번호") 가로 병합, `L3`="재단 장학금", `L4`="계", `M4~P4`= 은행명/은행코드(WINS)/은행코드(WRIS)/계좌번호.
- 데이터 5~49행(45명). 행 높이 14.1 고정(customHeight).
- 합계 50행: `K50`=`N시간` 형식 문자열, `L50`=금액 합(숫자). **수식이 아닌 값**이다. 합계 행의 A~J는 빈 서식 셀.
- `N`, `O`: `=VLOOKUP(M5,은행코드!$B$2:$C$79,2,0)`, `=VLOOKUP(M5,은행코드!$B$2:$D$79,3,0)` (타입 `str`, 결과값 캐시됨).
- 열 형식: `D`(학번) 숫자, `P`(계좌) 문자열, `I`,`J`,`L` 숫자 `#,##0_ `, `K` 문자열, `B` 문자열(8자), `A` 숫자, `Q` 비고 비어 있음.
- 자동 필터 `C3:G4`(`_xlnm._FilterDatabase`, 숨김 이름). 조건부 서식 `duplicateValues`가 `D5:D7 D20:D25`에만 걸려 있음(전체 범위 아님 → 이전 작업 흔적).
- 인쇄 설정: A4 세로, 여백 기본. **Print_Area, Print_Titles 이름 정의 없음.**
- 시트 기본 행 높이 16.5, 열 너비는 열마다 지정(A=3.75 등).

|---|---|---|
| A | 근로구분명 | 상수 문자열 `<근로구분명 상수>` |
| B | 년도 | 숫자(연도) |
| C | 월 | 숫자 `9` |
| D | 학번 | 숫자, 지급대상자명단 `D`와 45행 모두 일치 |
| E | 근무부서코드 | 공란 |
| F | 근무일수 | 공란 |
| G | 재단 장학금 | `=VLOOKUP(D2,'지급대상자명단(9월)'!$D$5:$L$100,9,0)` |
| H | 은행코드 | `=VLOOKUP(D2,'지급대상자명단(9월)'!$D$5:$N$100,11,0)` (WINS 코드) |
| I | 계좌번호 | `=VLOOKUP(D2,'지급대상자명단(9월)'!$D$5:$P$100,13,0)` |

### 2.3 `WRIS` (헤더 1행, 데이터 2~46행)
| 열 | 헤더 | 샘플 내용 |
|---|---|---|
| A | gub_a | 상수 `<구분코드A>` |
| B | gub_b | 상수 `<구분코드B>` |
| C | verify_no | 학번(숫자), 명단 `D`와 일치 |

| G | account_no | `=VLOOKUP(C2,'지급대상자명단(9월)'!$D$5:$Q$100,13,0)` (`P`열) |

### 2.4 `은행코드`
- `A`, `B` 모두 은행명(78행에서 값이 전부 동일). 조회는 `B` 기준.
- `C` WINS 코드: **78개 중 37개가 공란**. `D` WRIS 코드: 공란 0개.
- 은행명 1건이 중복(정확 일치 VLOOKUP은 첫 행을 반환).
- `C` 셀 타입이 숫자/문자열 혼재.
- 샘플 45명이 쓴 은행은 8종이며 모두 표에 있고 두 코드가 비어 있지 않음.

## 3. 입력 → 출력 교차 검증 (샘플 한정, 자동 대조)
- 입력 3~47행 vs 지급대상자명단 5~49행: 매핑된 13개 열(D,E,F,G,H,I,J,K,L,M,O,T,U) **불일치 0건**, 순번도 일치.
- 학번 중복 0건. 학번 길이 8자리 고정.
- 금액 합계: 입력 `O`의 행 합 = 입력 `O48` = 명단 `L`의 행 합 = 명단 `L50`. 일치.
- 시간 합계: 각 행의 시간을 **분으로 환산해 합산**하면 입력 `M48`·명단 `K50`과 일치. 시간만 더하면 1580이므로 분 단위 합산 규칙이 맞다. **합이 정확히 나누어떨어지지 않을 때의 표기는 샘플로 확인 불가.**
- WINS `D`, WRIS `C`/`D`는 명단과 45행 모두 일치.

## 4. 보존 위험(openpyxl 실측 전 평가)
| 항목 | 위험 |
|---|---|
| `printerSettings*.bin` | openpyxl은 보존하지 않음 → 프린터 설정 손실 가능 |
| `calcChain.xml` | 행 추가·삭제 시 무효화됨. 삭제해야 복구 경고 없음 |
| 공유 수식 | WRIS `H` 등. 행 확장 시 수식 재작성 필요 |
| 조건부 서식 범위 | 인원에 맞춰 재설정해야 함(현재도 불완전) |
| 병합 | 합계행에는 병합 없음. 헤더 병합만 고정 위치 |
| 행 높이·열 너비 | 템플릿 행 스타일 복제 필요 |
| 수식 캐시 값 | openpyxl로 저장하면 수식 결과 캐시가 사라져 Excel 외 도구에서 값이 비어 보일 수 있음 |
| 숫자 서식 | 학번이 숫자 타입 + 텍스트 서식(`@`) 혼합 |

## 5. 인원 변화(N) 시 구조적 영향 정리
- 명단: 데이터 행 5~(4+N), 합계 행 5+N. 템플릿은 45행 기준이라 N≠45이면 행 삽입·삭제와 합계 이동이 필요하다.
- WINS/WRIS: 데이터 행 2~(1+N).
- WINS/WRIS의 VLOOKUP 상한이 `$100`이라 명단 5~100행, 즉 **N ≤ 96에서만 정상**. N=120은 수식 방식을 유지하면 깨진다.
- 조건부 서식, 자동 필터, `_FilterDatabase` 이름 정의는 N에 맞춰 갱신해야 한다.

## 6. 아직 확인하지 못한 것
- 셀 스타일(글꼴/색/테두리/정렬)의 상세 값과 행별 편차(합계행 스타일 포함).
- Excel에서 열었을 때의 복구 경고 여부, 수식 재계산 결과, 인쇄 미리보기.
- `A`/`B`/`V`/`W`/`X` 입력 열의 업무 의미.
- 마스킹본에 실제 기관명·사업자번호가 남아 있는지(커밋 전 검토 필요).

## 9. 확장·축소 실험 (합성 데이터, 방식 A vs B)
- 스크립트: `tools/experiments/exp.py` (사용법은 같은 폴더 `README.md`). 합성 데이터로 N=1/32/45/70/120을 각 방식으로 생성하고 템플릿과 비교. 결과 xlsx는 저장소에 보관하지 않는다.
- **방식 A**: 템플릿을 열어 `delete_rows`/`insert_rows`로 행 수를 맞추고 값을 덮어씀.
- **방식 B**: 템플릿을 열되 데이터 블록(행 5~끝)을 지우고, 템플릿의 `첫 행/중간 행/합계 행` 스타일(`_style`)과 행 높이를 복제해 N행을 재구성. 합계 행을 5+N에 새로 만들고, 조건부 서식을 데이터 범위 1개 규칙으로 재작성. WINS/WRIS도 동일.
- 공통: WINS/WRIS는 **값으로 기록**, 명단 `N`,`O`는 `VLOOKUP` 수식 유지, 학번·계좌는 문자열, `wins 업로드 결과(2.9)` 시트 제외.

### 9.2 방식과 무관하게 openpyxl 저장 시 달라지는 것 (무수정 round-trip 기준)
| 항목 | 영향 |
|---|---|
| `printerSettings1~4.bin` 삭제 | 프린터별 설정 소실. 용지·방향·여백은 유지. 대부분 문제 없으나 프린터 지정은 사라짐 |
| `calcChain.xml` 삭제 | 무해(Excel이 재생성). 복구 경고 방지에는 오히려 유리 |
| 수식 캐시 값 소실 | 명단 `N`,`O`는 Excel 외 도구에서 빈 값. 저장 시 `fullCalcOnLoad=1` 기록되어 Excel은 열 때 재계산 |
| 문자열 저장 방식 | 이 환경의 openpyxl은 문자열을 inline(`t="inlineStr"`)으로 기록, `sharedStrings.xml`이 없음. 규격상 유효하나 Excel 저장 시 변환됨 |
| 시트 `.rels`, 확장 속성(예: `dyDescent`) | 삭제됨 |
| 숨김 `_FilterDatabase` | WINS 쪽 잔재는 사라짐(자동 필터 요소가 없었기 때문) |

## 10. 개인정보 점검 결과 (수치·값은 비공개 노트에만 기록)
- 성명, 학번, 계좌, 사업자등록번호, 활동기관·근로지 이름이 모두 **실제 값으로 보이거나 재식별 가능성이 있다**고 판단한다. 마스킹이 일부 적용된 필드(계좌 등)도 있으나 완전하다고 볼 수 없다.
- 결론: 마스킹 샘플은 **공개 안전성이 확인되지 않았다.** 저장소에 커밋하지 않으며, 테스트는 완전 합성 데이터만 사용한다(`docs/PUBLIC-SAFETY.md`).
- 이 문서에는 위 필드의 값, 종류 수, 형식 분포를 기록하지 않는다.
