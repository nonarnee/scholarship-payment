# 제품 요구사항

## 1. 업무 배경 및 목표
매월 재단의 '월별지급승인' 파일을 근거로 대학 내부용 '지급명단' 엑셀 파일을 만든다. 지급명단의 모든 핵심 시트가 실제 업무에 사용된다.

| 출력 시트 | 사용 업무 | 의무 |
|---|---|---|
| 지급대상자명단(해당 월) | 지출결의서 | 필수 |
| WINS | 학교 전산 입력 | 필수 |
| WRIS | 지급대상자 다중입력 | 필수 |
| 은행코드 | WINS/WRIS 상이한 코드 체계 참조 | 유지 |
| wins 업로드 결과(2.9) | 과거 업로드 결과 참고 | 기본 제외 |

## 2. 지원 사업
- 대학생 청소년교육지원장학금(대청교)
- 다문화·탈북학생 멘토링장학금(다문화멘토링)
- AI멘토링

사업별 월별지급승인 파일의 구조가 서로 다를 수 있다. **사업별 입력 파일 처리와 표준 출력 파일 생성을 분리**한다. 현재 자세한 입력 샘플이 있는 사업은 대청교뿐이다.

## 3. UX / 결과물
- 사업 유형 선택 → 월별지급승인 파일 선택 → 지급연월/대상자 수/합계 사전 확인 → 저장 위치 선택 → 생성.
- 결과는 Excel 통합문서 1개에 필수 시트 3개 + 은행코드 참조표. 기본은 통합 1개 파일이고, 사용자가 선택하면 명단·WINS·WRIS 를 시트별 3개 파일로 새 하위 폴더에 따로 저장한다(2026-11-09 결정, `DECISIONS-OPEN.md` D).
- 기본 파일명 제안: `지급명단_{사업코드}_{YYYY}_{MM}.xlsx` (최종 업무 명명 규칙 확인 필요).
- 완전 오프라인 동작, 외부 데이터 전송 없음, 인터넷 불필요.
- 대상자 수는 고정되지 않는다. 45명은 한 달의 샘플일 뿐이다.
- 대상자 0명은 안내 후 생성 중단(정책 가안).
- 다른 사업에 같은 학번이 등장하는 것은 자동 오류로 처리하지 않는다. 한 파일 내 중복 검증은 업무 규칙 확인 후 적용.

## 4. Excel 보존
- 기존 **마스킹 지급명단**을 기준 템플릿으로 사용한다.
  > 공개 저장소 정책 주석: 마스킹 샘플 자체는 저장소에 두지 않는다(`PUBLIC-SAFETY.md`). 저장소에는 같은 레이아웃의 **합성 템플릿**(`templates/synthetic_payment_template.xlsx`)만 두고, 실제 템플릿은 비공개로 주입한다. 요구사항의 의미는 바꾸지 않는다.
- 색상, 글꼴, 굵기, 셀 테두리, 정렬, 숫자 형식, 병합, 행 높이, 열 너비, 수식, 인쇄 영역, 페이지 설정을 유지하거나 필요한 범위만 조정한다.
- 새 인원 수에 맞춰 표의 데이터 영역과 하단 합계를 재배치한다.
- 템플릿과 데이터 결합 과정에서 개인정보가 섞이거나 이전 월 데이터가 남지 않아야 한다.

## 5. 정책상 주의
- '동일한 출력 양식'은 **동일한 시트·열 형식**을 의미한다. 사업별 근로구분명, 코드값, 적요, 시급, 멘토/멘티 인원 등의 값까지 무조건 동일하다는 뜻은 아니다.
- 입력 파일에 없는 지급정보를 임의 계산·추정해서 만들지 않는다.
- 지급 대상자별 입금계좌 예금주 확인 정책은 별도 결정.
