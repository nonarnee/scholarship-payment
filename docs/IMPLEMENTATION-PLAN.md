# 구현 설계안 (설계·검증 단계 — 구현 전)

> 변환 엔진, GUI, EXE, GitHub Actions는 **아직 구현하지 않았다.** 이 문서는 설계와 구현 순서만 정한다.
> 근거: `FILE-STRUCTURE.md`(실측), `TEMPLATE-ANALYSIS.md`(openpyxl 실험), `FIELD-MAPPING.md`, `DECISIONS-OPEN.md`(결정), `OPEN-QUESTIONS.md`(미확정).
> **[결정]** = 사용자가 확정, **[실측]** = 샘플·실험으로 확인, **[방향]** = 우선 검토(최종 아님), **[미확정]** = OPEN-QUESTIONS 참조.

## 1. 구조
```
입력 xlsx ─▶ SourceAdapter(사업별) ─▶ PaymentBatch/PaymentRow ─▶ Validator
        ─▶ TemplateWriter(공통) ─▶ 출력 재검증(재로드 교차 검증) ─▶ 임시파일 ─▶ 최종 경로
```
- 입력 Adapter와 출력 Writer는 서로 import하지 않는다. 연결 고리는 `PaymentBatch`뿐이다.
- 사업은 사용자가 선택한다. Adapter는 헤더 지문(핵심 헤더 텍스트·병합 위치)을 검증하고, 다르면 **거부 + 진단**한다(열 번호를 조용히 적용하지 않는다).

### 1.1 Adapter
| 구현체 | 상태 |
|---|---|
| `DaechungAdapter` | 실측 기반으로 구현 가능(구현은 후속 지시 후) |
| `MulticulturalAdapter`, `AiMentoringAdapter` | **[결정] 실제 샘플 확보 전까지 구현하지 않는다.** 인터페이스 정의만 두고 "지원"으로 표시하지 않는다 |

공통 메서드: `verify_layout(wb)`, `read(wb) -> PaymentBatch`, `source_totals(wb)`(합계행 대조용).

### 1.2 모델 [결정]
- `PaymentRow`: `student_id`, `account_no`, `biz_no`는 **`str`**. 금액은 **`int`(원)**, `float` 금지. 활동시간은 **`minutes: int`**(출력 시 `N시간[M분]`로 변환).
- `PaymentBatch`: `program_code`, `year`, `month`, `rows`, `source_totals`, 파일 해시·시트명 등 메타(개인정보 제외).
- `BusinessOutputPolicy`: 사업별 상수(근로구분명, 구분코드 2종, 적요, 제목, 파일명, 기준일). 값은 확정 전까지 코드에 박지 않고 설정 데이터로 분리한다[미확정 H3, M6, M9].

### 1.3 읽기
- `openpyxl`로 **읽기만** 한다. 원본은 수정·저장하지 않는다. 암호/손상/잠김은 사용자 메시지로 구분한다.
- 입력의 `A`, `B`, `V`, `W`, `X`열은 읽지도, 필터에도 쓰지 않는다[결정].
- 학번이 숫자 셀로 들어오면 문자열화하되, 정확히 8자리가 아니면 BLOCK(선행 0 소실 의심)[샘플 한정 규칙, 길이 규칙은 미확정].

## 2. Validator (출력 전 모두 통과해야 함)
1. 레이아웃: 헤더 지문 일치, 합계행 존재.
2. 행 단위: 필수 필드, 학번 형식, 금액 정수·0 초과, 시간 패턴(`#시간`, `#시간#분`), `P+Q==O`(샘플 관찰, 정책 확정 전에는 WARN), 년월 일치.
3. 배치 단위: 모든 행의 년월 동일, 학번 중복(정책 미확정 H5 → 임시 BLOCK), 데이터 합(금액, 분) == 입력 합계행.
4. 은행코드 **[결정]**: 은행명 정확 일치. WINS 코드·WRIS 코드를 각각 변환하고, **필요한 코드가 없거나 모호하면 BLOCK**.
5. 0명 → 중단 안내(임시, M10). N ≥ 1이면 상한 없음. 120명 이상 지원.

오류가 하나라도 있으면 **파일을 만들지 않는다.** 진단 보고서에는 행 번호·필드명·규칙 코드만 담고 이름·학번·계좌 값은 담지 않는다.

## 3. TemplateWriter — 방식 A/B 비교와 권장안

### 3.1 비교 (근거: `TEMPLATE-ANALYSIS.md` §9, 합성 데이터 N=1/32/45/70/120)
| 기준 | 방식 A: 템플릿에 행 삽입·삭제 | 방식 B: 스타일 복제 + 데이터 블록 재구성 |
|---|---|---|
| 데이터 행 스타일 보존 | N≠45에서 삽입 행이 **스타일 없음**(70명: 명단 456/1190셀, 120명: 1306/2040셀 불일치) | **불일치 0** (전 N, 세 시트) |
| 행 높이 | 삽입·삭제 행에서 어긋나고 합계 행 높이가 소실(70·120명) | 전 행 일치. 템플릿 41~49행(미지정)은 14.1로 통일 |
| 합계 행 | 위치·값 정상이나 행 높이·잔여 서식 문제 | 위치 5+N, 값·스타일·높이 정상 |
| 합계 행 아래 잔여 | 축소 시 이전 서식 행 잔류(N=1: 34행) | 없음 |
| 조건부 서식 | 24조각 그대로, 새 행 미커버 | 데이터 범위 1규칙으로 재작성 |
| 병합·열 너비·자동 필터·탭 색·페이지 설정 | 보존 | 보존 |
| 학번/계좌 문자열 | 선행 0 보존 | 선행 0 보존 |
| 명단↔WINS↔WRIS 교차 일치 | 통과 | 통과 |
| 구현 복잡도 | 낮음, 그러나 N≠45마다 보정 코드가 필요 | 중간(스냅샷 3종: 첫 행/중간 행/합계 행) |
| openpyxl 공통 한계 | printerSettings·calcChain·수식 캐시·sharedStrings 방식 변경 | 동일 |

### 3.2 최종 권장안: **방식 B**
- 템플릿을 로드해 시트 단위 속성(헤더, 병합, 열 너비, 필터, 탭 색, 페이지 설정, 은행코드 시트)을 그대로 승계하고, 데이터·합계 블록만 재구성한다.
- 스냅샷 3종을 **템플릿의 해당 행에서 복제**한다: 첫 데이터 행(전체 테두리), 중간 행, 합계 행. 3 변형을 하드코딩하지 않는다.
- 합계 행은 5+N에 재작성. 조건부 서식은 템플릿 규칙의 dxf를 재사용해 단일 범위로 재작성[미확정 M11: 유지/삭제].
- WINS/WRIS: [방향] 값 기록. 같은 스냅샷 방식으로 행을 재구성한다. 수식 병행 옵션은 업로드 검증(H1) 후 결정.
- 학번 출력 셀 타입은 H2에 따라 결정. 문자열이면 선행 0 보존이 실험으로 확인됨.
- 명단 `N`,`O`: 수식 유지 시 캐시 값이 없어 Excel 외 도구에서 빈 값 → M4 결정 전까지 두 안(수식/값) 모두 Writer가 지원 가능하도록 설계한다.
- 한계: 프린터별 설정(`printerSettings*.bin`) 소실, 수식 캐시 소실(`fullCalcOnLoad=1`로 Excel은 재계산). **Windows Excel 열기 경고·인쇄 미리보기는 미검증.**

### 3.3 인원 N 처리 (실험으로 N=1/32/45/70/120 확인)
- 명단 데이터 행 5~(4+N), 합계 행 5+N. WINS/WRIS 데이터 행 2~(1+N).
- 값 기록 방식이므로 96명 상한이 없다(수식 유지 시에만 상한 문제).
- 0명은 중단(M10).
- 120명 이상 시 인쇄 페이지가 늘어난다. 제목 행 반복 여부는 L1.

### 3.4 저장 [결정: 덮어쓰기 금지]
- 임시 파일에 저장 → 재로드 후 시트 목록, 행 수, 합계, 학번·계좌·은행코드 교차 검증 → 성공 시에만 최종 경로로 이동. 실패 시 임시 파일 삭제.
- 최종 경로에 같은 이름이 있으면 **절대 덮어쓰지 않고** 다른 이름 제안 또는 사용자 확인.
- 파일 잠김·권한 오류는 구분된 메시지로 안내. 원본 입력 파일은 읽기만 한다.

## 4. 오류 처리·진단
- 등급: `BLOCK`(출력 중단), `WARN`(진행 가능, 보고서에 표기).
- 보고서: 규칙 코드, 시트, 행 번호, 필드명, 설명. **값 미기재.** 로그·예외 메시지에 셀 값, `repr(row)` 금지.

## 5. 개인정보·Git·공개 저장소 [결정/실행됨]
- **공개 저장소 규칙, 합성 데이터, 검사 체계는 `PUBLIC-SAFETY.md`를 따른다.** 실제 헤더·상수·템플릿은 코드에 넣지 않고 비공개 설정으로 주입하며, 공개 빌드에는 합성 템플릿만 포함한다.
- 테스트 fixture는 `tools/synthetic/make_synthetic.py`로 생성한 `synthetic_*.xlsx`만 사용한다.
- `.gitignore` 반영: `samples/`, `*.xlsx`, `*.xlsm`, `*.xls`, `*.csv`, `.DS_Store`, `.venv/`, `__pycache__/`, `.pytest_cache/`, 생성 결과·임시 폴더. 합성 fixture만 `tests/fixtures/synthetic/`에 예외 허용.
- 마스킹 샘플은 공개 안전성이 확인되지 않았으므로 **커밋 금지**(`PUBLIC-SAFETY.md`). 테스트는 합성 데이터(가상 이름·학번·계좌)만 사용한다.
- 커밋은 사용자 지시가 있을 때만 한다.

## 6. 빌드·배포 (미착수)
- GitHub Actions Windows runner에서 PyInstaller로 exe 빌드(macOS→Windows 크로스 컴파일 불가). 개발 환경은 Python 3.13.3(3.12 미설치)이므로 빌드 단계에서 버전 확정.
- 서명 없는 exe의 학교 PC 보안정책 대응은 L4. Windows 10/11 + 실제 Excel UAT 전에는 "완료"라고 표현하지 않는다.

## 7. 후속 구현 순서 (사용자 지시 후)
> 진행 상황: 1~6 구현됨(합성 데이터 기준, `PROJECT-STATUS.md`). 6번의 "명령줄"은 `python -m scholarship_payment convert …`. 7~9와 실자료·Windows Excel 검증은 미착수.
1. 프로젝트 골격(`pyproject.toml`, `src/`, `tests/`), 합성 fixture 생성기.
2. 모델·정규화(시간 파서→분, 식별자 문자열) + 단위 테스트.
3. `DaechungAdapter` + 레이아웃 검증 + 진단 보고서.
4. Validator + 시스템별 은행코드 변환(필요 코드 없으면 BLOCK).
5. 방식 B TemplateWriter(명단→WINS→WRIS) + N 매트릭스 테스트(0/1/32/45/70/120).
6. 재로드 검증 + 안전 저장(무덮어쓰기) + 45명 합성 필드 일치 테스트.
7. Tkinter GUI. 8. PyInstaller + Windows Actions + Windows 실검증.
9. 다문화·AI멘토링 Adapter는 각 샘플 확보 후에만 구현.

## 8. 구현 전 남은 검증
- Windows Excel: 방식 B 출력물 열기 경고, 수식 재계산, 인쇄 미리보기.
- 전산 업로드: WINS/WRIS 값 기록본 수용 여부(H1), 학번 셀 타입(H2).
- 다른 월 샘플로 레이아웃 불변 여부.
