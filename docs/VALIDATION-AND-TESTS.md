# 검증·테스트 기준

## 입력 검증
- 파일 열기 실패/암호 설정/손상/예상 시트·헤더 불일치
- 지급연월 파싱 및 한 파일에 여러 월이 섞여 있는지 확인
- 유효 행 검출: 헤더, 빈행, 합계행, 안내문을 실제 지급 대상으로 세지 않음
- 학번, 성명, 은행, 계좌, 지급금액 필수값 검증
- 계좌번호/학번 문자열 처리, 앞자리 0 및 하이픈 보존, Excel 자동 숫자 변환 방지
- Excel 수식 주입 가능 문자열 방어; 표시 문자열과 수식 생성 여부 구분
- 금액 정수 원 단위로 처리하고 음수/0원 처리 정책 확인
- 은행명 표준화 후 WINS/WRIS 각각의 유효 코드가 있는지 검사
- 동일 사업·동일 월·동일 학번 중복 처리 정책 확인

## 출력 및 왕복 검증
- 입력 유효 대상자 N명 = 명단 N명 = WINS N명 = WRIS N명
- 각 대상자 지급금액 입력→각 시트 일치, 총액 일치
- 순번, 학번, 계좌, 은행 및 예금주 값 교차 비교
- 원본 템플릿에 있던 지난달 데이터가 결과에 남지 않을 것
- 지급대상자명단·WINS·WRIS에서 연결 수식이 있다면 참조 유효성 검사
- 참조 없는 사후 사용 파일은 재계산이 필요한지 확인: openpyxl은 수식 계산 엔진이 아니므로 Excel 재계산 여부 주의
- 병합 범위 충돌 없음, 헤더 보존, 스타일/테두리, 합계/인쇄영역/페이지 나눔 확인
- 생성된 .xlsx를 Excel에서 열 때 복구 경고 없음

## 테스트 매트릭스
| 시나리오 | 기대 결과 |
|---|---|
| 0명 | 안내·생성 중단(확정 전 정책) |
| 1명 | 단일행·합계·서식 정확 |
| 32명 | 기존 45행 대비 축소, 잔존 데이터 없음 |
| 45명 | 참조 샘플과 필드별 일치 검증 |
| 70명 | 행·수식·병합·인쇄범위 확대 |
| 120명 | 성능과 서식 안정성 |
| 은행 코드 없음 | 오류, 결과 파일 미생성 |
| 헤더 변경 | 자동 오인식 없이 명확한 진단 |
| 중간 빈 행·마지막 합계 | 행 수 오검출 없음 |
| 계좌 앞자리 0 | 문자열 그대로 유지 |
| 파일 잠금·저장 권한 없음 | 원본/기존 결과 보호, 오류 표시 |
| 데이터 검증 실패 | 부분 성공 파일 없음 |
| 서로 다른 사업에서 같은 학번 | 사업 독립 처리 |

## 샘플 보안
- 실제 개인정보는 테스트 fixture에 넣지 않는다.
- 마스킹된 예시도 사업자번호·기관명 등 잔존 민감 정보 여부를 검토한 뒤 저장소에 포함한다.
- 로그에서는 계좌번호와 학생 식별정보를 표시하지 않는다.
