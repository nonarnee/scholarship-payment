# 검증·테스트 기준

> 작업 절차는 `WORKFLOW.md`, 현재 충족 현황은 `PROJECT-STATUS.md`.
> 이 문서의 기준은 **측정 가능한 합격 조건**이다. 기준을 완화하는 변경은 사용자 결정이다(`CLAUDE.md` §6).
> 허용 오차는 별도 표기가 없으면 **0**이다. 입력 값은 모두 합성 데이터(`tools/synthetic/make_synthetic.py`)를 쓴다.
> "자동화" 열: ✅ 테스트로 실행 중 / 🔶 탐색 스크립트로만 측정(테스트 아님) / ⬜ 미구현 / 🖐 Windows Excel·업로드 시스템 수동 확인 필요.

## 1. 데이터 정합성 기준 (DI)

| ID | 기준 (합격 조건) | 측정 방법 | 자동화 |
|---|---|---|---|
| DI-01 | 입력 유효 대상자 N = 명단 행 수 = WINS 행 수 = WRIS 행 수 (N = 1, 32, 45, 70, 120, 그리고 120 초과 1건) | 출력 재로드 후 행 수 계산 | ✅ 입력 측(Adapter, N=1~1000) / ⬜ 출력 행 수 |
| DI-02 | 대상자별 지급금액: 입력 승인금액 = 명단 = WINS = WRIS (정수 원, 불일치 0건) | 학번 키로 4곳 비교 | ✅ 입력 측(원본 형태 합성 대조) / ⬜ 출력 교차 |
| DI-03 | 총액: 입력 합계행 = 명단 합계 = 행 합계 (불일치 0원) | 정수 합산 비교 | ✅ 입력 합계행 대조(Adapter) / ⬜ 출력 합계 |
| DI-04 | 학번·계좌번호: 입력 문자열과 출력 문자열이 완전 일치(길이·앞자리 0·하이픈). 세 시트 교차 일치 | 문자열 `==` 비교, 선행 0 케이스(`00NNNNNN`) 포함 | ✅ 정규화 + Adapter(파일→모델 문자열 보존) / ⬜ 시트 간 교차 |
| DI-05 | 성명·은행명·순번이 시트 간 일치 | 학번 키 비교 | ⬜ |
| DI-06 | 은행코드: 시스템별(WINS/WRIS) 코드 = 은행코드표의 해당 열 값. 코드 없음·공란·이름 중복(모호) 시 **출력 파일 0개** + BLOCK 진단 | 합성 은행코드표(공란·중복 포함)로 시험 | ⬜ |
| DI-07 | 활동시간: 분 정수 합계 = 입력 합계행의 분 환산. 출력 표기는 `N시간[M분]` 규칙 | 시간 파서·합계 비교 | ✅ 시간 파서·왕복 + 입력 합계행 분 대조 / ⬜ 출력 표기 |
| DI-08 | 잔존 데이터: 템플릿의 이전 월 데이터가 결과에 0셀 | 합계 행 아래·데이터 영역 외 값 스캔 | 🔶 (합계 행 아래 값 0 확인) |
| DI-09 | 중복 학번: 정책 확정 전에는 **BLOCK**(임시). 사업이 다르면 오류 아님 | 합성 중복 입력 | ⬜ (정책 OPEN H5) |
| DI-10 | 입력 원본 불변: 처리 전후 SHA-256 동일 | 해시 비교 | ✅ Adapter가 원본 해시·mtime 불변 / ⬜ 전체 파이프라인 |
| DI-11 | 실패 시 최종 경로에 새 파일 0개, 임시 파일 0개(부분 성공 파일 금지) | 오류 주입 후 디렉터리 스캔 | ⬜ |
| DI-12 | 기존 출력 파일 덮어쓰기 0회(동일 이름이면 중단 또는 다른 이름) | 사전 생성한 파일의 해시 비교 | ⬜ |
| DI-13 | 개인정보 비노출: 로그·예외·진단 보고서·테스트 출력에 이름·학번·계좌 값 0건 | 합성 값을 심고 캡처한 출력에서 검색 | ✅ 오류 객체·모델 repr·Adapter 오류 보고 값 비노출 / ⬜ 로그·진단 보고서 파일 |
| DI-14 | 수식 주입 방어: `=`, `+`, `-`, `@`로 시작하는 입력이 수식으로 기록되지 않음 | 합성 입력 | 🔶 탐지 helper(`is_formula_like`)만 ✅ / ⬜ Writer 기록 방어 |
| DI-15 | 금액은 정수 원: 소수·문자 혼입 입력은 BLOCK, 내부 `float` 사용 0 | 입력 변이 테스트 | ✅ 금액 정수 파싱·float 합계 방지 / ⬜ Validator 전체 |

## 2. 서식 보존 기준 (FP)
기준 파일: `templates/synthetic_payment_template.xlsx`(합성). 비교 대상: 같은 N의 생성 결과.
"스타일 시그니처" = 글꼴명·크기·굵기·채움색·테두리 4변·가로/세로 정렬·줄바꿈·숫자 형식.

| ID | 기준 (합격 조건) | 측정 방법 | 현재 실측 (합성 템플릿, 방식 B) | 자동화 |
|---|---|---|---|---|
| FP-01 | 헤더 영역(명단 1~4행, WINS·WRIS 1행) 스타일 시그니처 불일치 0셀, 헤더 행 높이 동일 | 셀 단위 시그니처 비교 | 불일치 0 | 🔶 |
| FP-02 | 데이터 행 스타일 시그니처 불일치 0셀(첫 행/이후 행 기준 행 대비) | 셀 단위 비교, N별 | N=1/32/45/70/120 모두 0 (명단·WINS·WRIS) | 🔶 |
| FP-03 | 병합 범위 집합 = 템플릿(헤더). 데이터·합계 영역 병합 충돌 0 | 병합 집합 비교 | 동일 | 🔶 |
| FP-04 | 열 너비 모든 열 동일 | 열 너비 비교 | 동일 | 🔶 |
| FP-05 | 행 높이: 헤더·합계 동일, 데이터 행 = 기준 행 높이. (템플릿 데이터 행 높이 불균일은 정책 OPEN L2) | 행 높이 비교 | 합계·헤더 동일, 데이터 행 기준 행으로 통일 | 🔶 |
| FP-06 | 합계 행: 위치 = 데이터 끝 + 1, 스타일 동일, 값 = 계산값(DI-03·07) | 위치·값·시그니처 | 위치·스타일 정상 | 🔶 |
| FP-07 | 합계 행 아래 잔여 서식 행(커스텀 높이 포함) 0 | 행 속성 스캔 | 0 | 🔶 |
| FP-08 | 조건부 서식: 데이터 영역 전체를 덮는 범위, 조각난 범위 0 (유지 여부 OPEN M11) | 범위 비교 | 데이터 범위 1개 규칙 | 🔶 |
| FP-09 | 자동 필터 범위·탭 색·용지·방향·여백 동일 | 속성 비교 | 동일 | 🔶 |
| FP-10 | 수식: 값 기록 시트(WINS·WRIS)의 수식 0개(정책 OPEN H1 확정 전 방향). 명단 `N`/`O` 수식 유지 시 모든 행이 자기 행을 참조 | 수식 패턴 검사 | 수식 0개, 참조 N/N행 정상 | 🔶 |
| FP-11 | 알려진 손실 외 손실 0: 허용 손실 = `printerSettings`, `calcChain`, 수식 캐시 값, 문자열 저장 방식 | 패키지 파트 diff | 위 허용 손실 외 없음 | 🔶 |
| FP-12 | 재로드 오류 0(openpyxl), 시트 목록 = {명단, WINS, WRIS, 은행코드} (이력 시트 제외) | 재로드 | 통과 | 🔶 |
| FP-13 | **Excel에서 열 때 복구 경고 0**, 수식 재계산 정상, 인쇄 미리보기 정상 | Windows Excel 수동 확인 | **미검증** | 🖐 |
| FP-14 | 대조 기준(방식 A)에서는 FP-02가 깨짐을 확인(회귀 감시용 기준선): N=70에서 명단 425/1190셀 불일치 | 비교 스크립트 | 방식 A 불일치 확인됨 | 🔶 |

## 3. 입력 검증 항목
- 파일 열기 실패/암호 설정/손상/예상 시트·헤더 불일치 → 진단 후 중단
- 지급연월 파싱, 한 파일에 여러 월이 섞였는지 확인
- 유효 행 검출: 헤더, 빈 행, 합계 행, 안내문을 실제 지급 대상으로 세지 않음
- 학번, 성명, 은행, 계좌, 지급금액 필수값 검증
- 학번 형식: 샘플 관찰은 8자리(규칙 확정 전, 길이 불일치는 BLOCK)
- 금액 정수 원 단위, 음수/0원 처리 정책 확인(OPEN H5)
- 입력의 `A`·`B`·`V`·`W`·`X`열은 지급 대상자 필터에 사용하지 않는다(결정)

## 4. 테스트 매트릭스
| 시나리오 | 기대 결과 | 관련 기준 |
|---|---|---|
| 0명 | 안내·생성 중단(확정 전 정책) | DI-11 |
| 1명 | 단일 행·합계·서식 정확 | DI-01~03, FP-02,06 |
| 32명 | 기존 45행 대비 축소, 잔존 데이터·서식 없음 | DI-08, FP-07 |
| 45명 | 합성 참조 템플릿과 필드별 일치 | DI-01~05, FP 전체 |
| 70명 | 행·병합·조건부 서식·인쇄 범위 확대 | FP-02,03,08 |
| 120명, 120 초과 | 정상 완료, 서식 안정(96명 상한 없음) | DI-01, FP-02 |
| 은행 코드 없음/공란/이름 중복 | 오류, 결과 파일 미생성 | DI-06, DI-11 |
| 헤더 변경 | 자동 오인식 없이 명확한 진단 | 입력 검증 |
| 중간 빈 행·마지막 합계 | 행 수 오검출 없음 | DI-01 |
| 학번·계좌 앞자리 0, 하이픈 | 문자열 그대로 유지 | DI-04 |
| `=`·`+`·`-`·`@` 시작 문자열 | 수식으로 기록되지 않음 | DI-14 |
| 소수·문자 금액 | BLOCK | DI-15 |
| 파일 잠금·저장 권한 없음 | 원본·기존 결과 보호, 오류 표시 | DI-10~12 |
| 데이터 검증 실패 | 부분 성공 파일 없음 | DI-11 |
| 같은 학번이 다른 사업에 존재 | 사업 독립 처리 | DI-09 |

## 5. 샘플·테스트 데이터 보안
- 테스트 fixture는 **완전 합성 데이터**만 쓴다(`tools/synthetic/make_synthetic.py`, `synthetic_*.xlsx`).
- **마스킹된 실제 자료도 저장소에 포함하지 않는다**(공개 안전성 미확인, `PUBLIC-SAFETY.md`). 실제 자료로 하는 분석은 로컬(`samples/`, `private/`)에서만 하며 결과의 값·통계를 공개 문서에 옮기지 않는다.
- 로그·예외·진단 보고서에는 계좌번호와 학생 식별정보를 표시하지 않는다(행 번호·필드명·규칙 코드만).
- 모든 변경은 `tools/safety/check_public_safety.py`를 통과해야 한다(자체 시험: `tests/test_public_safety.py`).

## 6. 항상 실행하는 명령

.venv/bin/python -m pytest -q tests
python3 -I tools/safety/check_public_safety.py --worktree
