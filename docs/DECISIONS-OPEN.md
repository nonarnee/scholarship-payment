# 결정 사항과 미확정 사항

> 결정은 사용자가 내린 것만 적는다. 샘플·실측으로 알게 된 사실은 `FILE-STRUCTURE.md`, 미확정은 `OPEN-QUESTIONS.md`(근거·영향도 포함)에서 관리한다.

## A. 확정된 결정
### 제품·범위
- Windows 사용자용 오프라인 데스크톱 실행파일. macOS + Claude Code로 개발, Windows에서 빌드·실검증.
- 사업 3개(대청교 / 다문화·탈북학생 멘토링 / AI멘토링). 표준 출력 서식은 단일. 미제공 양식은 추정하지 않으며 **다문화·AI멘토링 Adapter는 실제 샘플 확보 전까지 구현하지 않는다.**
- 필수 출력 시트 3개(`지급대상자명단(해당 월)`, `WINS`, `WRIS`) + `은행코드` 참조 시트. `wins 업로드 결과(2.9)`는 기본 제외. 결과는 기본이 다중 시트 1개 파일이며, 사용자가 선택하면 명단·WINS·WRIS 를 시트별 3개 파일로 따로 저장할 수 있다(아래 2026-11-09 결정).
- 대상자 수는 고정하지 않는다. **1명부터 120명 이상**을 지원한다.
- 기존 지급명단의 셀 스타일, 병합, 수식, 행 높이, 열 너비, 인쇄 설정을 **최대한** 보존한다.
- 원본 입력 파일을 변경하지 않고, 기존 출력 파일을 무단으로 덮어쓰지 않는다.

### 데이터 처리
- 내부 학번·계좌번호는 **문자열**로 처리한다. (출력 셀 타입은 템플릿·업로드 시스템 요구에 맞춰 별도 결정 → OPEN-QUESTIONS)
- 지급금액은 **재단 승인금액**(입력 `재단 장학금 계`)을 기준으로 한다. 금액은 정수 원 단위.
- 활동시간은 내부에서 **분 단위 정수**로 처리하고 출력 형식에 맞춰 변환한다.
- 은행코드는 출력 시스템별(WINS용, WRIS용)로 **개별 변환**한다. 지급 대상자의 필요한 은행코드가 없거나 모호하면 **지급명단 생성을 차단**한다.
- 입력의 `A`, `B`, `V`, `W`, `X`열은 의미 확인 전까지 **지급 대상자 필터 조건으로 사용하지 않는다.**

### 공개 저장소 [결정]
- 이 프로젝트는 **GitHub Public 저장소**로 공개한다. 실제 업무자료와 공개용 테스트 데이터를 엄격히 분리한다(`PUBLIC-SAFETY.md`).
- 기존 마스킹 파일은 공개 안전성이 확인되지 않았으므로 **커밋하지 않는다.** 테스트용 엑셀은 완전 합성(학생·기관·금액) 데이터로 별도 생성한다.
- 설계 문서에도 실제 기관정보, 내부 시스템 식별값, 업무자료에서 추출한 값을 쓰지 않는다. 저장소에는 공개 가능한 코드·문서·합성 템플릿만 포함한다.

### 2026-11-03 사용자 확정
- WINS·WRIS·명단 은행코드(N/O)는 수식 대신 **값으로 기록**한다(문제없음 확인). 수식을 쓰던 이유는 정확도였으므로, 정확도는 Writer의 독립 계산과 출력 재검증으로 대신 보장한다. (학번·은행코드 **셀 타입**의 업로드 수용은 별도 미확인: OPEN H2/M21)
- 중복 학번·0원 행은 **결과물에 없어야** 한다. 현재는 이를 차단(BLOCK)으로 구현했다(자동 제외 아님. OPEN M17).
- 명단 `Q2` 기준일은 **작성일**(변환 실행일, `YYYY.MM.DD`). `--base-date`로 덮어쓸 수 있다.
- 출력 파일명은 **현행 유지**(`{접두}_{사업코드}_{YYYY}_{MM}.xlsx`, 같은 이름이 있으면 `_2`…). 학교 표준 이름 없음.
- GUI·Windows Excel 실검증은 **나중으로 미룬다**(원격 세션이라 불가).
- 다문화 결과 파일은 대청교와 같은 양식. 학생당 1행(기관 변경·이월로 행이 여럿이면 시간·금액은 합계, 나머지는 맨 위 행). 사업자등록번호 열은 공란+숨김. 시급은 근무형태별 고정 시급표(정책 파일)에서 찾고 계산하지 않는다. 근로지=기관명, 멘티 인원=1. 시급이 다른 기관이 섞이면 시급 칸에 `위 행 / 아래 행`으로 둘 다 표시. 이월 행은 근무형태 앞 활동월이 지급월과 다르며, 연도 변경은 지급월 1·2월(학년도 경계)에만 해당.
- 정책에서 학년도·학기는 제목에 넣지 않는다. 은행코드 표는 사용자가 템플릿에서 직접 보완한다.

### 2026-11-06 사용자 확정 (재단 원본 시트 선택)
- 재단 원본의 **시트명은 검사 조건이 아니다**(재단이 내려받는 파일의 시트명은 달라질 수 있다). 고정 시트명 검증은 제거한다.
- 대신 구조로 데이터 시트를 찾는다: 사업별 필수 머리글의 **값과 위치**, 필요한 **병합 구조**가 모두 일치하는 시트가 **정확히 1개**일 때만 쓴다. 없으면 구조 오류로, 2개 이상이면 모호한 입력으로 차단한다. 시트명을 추정하거나 첫 시트를 무조건 쓰지 않는다.
- 이 변경은 재단 원본 입력 Adapter의 시트 선택에만 적용한다. 학교 출력 템플릿의 시트 계약(`지급대상자명단`·`WINS`·`WRIS`·`은행코드`), Validator·Writer·safe_save·정책 계산 규칙은 그대로다. 열 위치를 자유롭게 바꾸는 동적 열 매핑은 하지 않는다.

## B. 아직 확정되지 않은 것
`OPEN-QUESTIONS.md`를 본다. 대표 항목: 업로드 호환성(수식 vs 값), 출력 학번 셀 타입, 사업별 상수(근로구분명·구분코드 2종·적요), 예금주 정책, 중복 학번, 0원·취소·음수 행, `Q2` 기준일, 0명 정책, 학교 PC 보안정책.

## C. 이전 문서 대비 변경
- 이전 "미확정 6번(금액 출처)", "미확정 10번(빈 코드 허용 여부)"은 A에서 결정됨(승인금액 기준, 필요한 코드 없으면 차단).
- 이전 "지급 대상자 필터" 관련 해석 여지는 A로 닫음(A/B/V/W/X 미사용).

## D. 2026-11-09 사용자 확정 (시트별 파일 저장)
- 결과 저장 방식을 **통합 1개 파일 / 시트별 3개 파일** 중 선택한다. **기본은 통합**(기존과 같음). 선택은 지급내역 확인 화면에서 하고 새 변환마다 기본으로 돌아간다.
- 시트별 저장은 저장 폴더 안에 **새 하위 폴더 하나**를 만들어 `<폴더명>_명단.xlsx`, `<폴더명>_WINS.xlsx`, `<폴더명>_WRIS.xlsx` 를 둔다. 폴더명은 통합 파일명에서 확장자를 뺀 것이고, 같은 이름이 있으면 폴더에 `_2`, `_3` 을 붙인다(기존 파일·폴더는 건드리지 않는다).
- 세 파일은 모두 임시 폴더에서 만들고 각각·서로 재검증을 통과한 경우에만 폴더째 공개한다. 하나라도 실패하면 아무 것도 공개하지 않는다.
- **가정(사용자 확인 대기)**: 분리 파일에 `은행코드` 시트는 넣지 않는다 / CLI 의 `--split` 은 이번 범위에서 제외 / Tk 는 새 기능을 적용하지 않는다. 시트 1개짜리 파일을 업로드 시스템이 받는지는 확인하지 못했다.
