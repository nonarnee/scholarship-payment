# 대청교 필드 매핑 (실제 셀 참조 기준)

> 범위: **대청교**(대학생 청소년교육지원) 한 사업만. 다문화·탈북학생 멘토링, AI멘토링은 샘플 미확보라 매핑하지 않는다(§5).
> 근거: `docs/TEMPLATE-ANALYSIS.md`. 열 번호는 샘플(1개월분) 기준이며, 코드는 열 번호가 아니라 **헤더 검증 후** 위치를 사용해야 한다.
> `[샘플]` = 샘플에서 관찰한 값(정책 미확정), `[확정 필요]` = DECISIONS/OPEN-QUESTIONS 연결.

## 1. 입력 `월별지급승인` → 공통 `PaymentRow`

| 입력 셀(3~47행) | 헤더(1~2행) | PaymentRow 필드 | 타입 | 변환 규칙 |
|---|---|---|---|---|

| E | 성명 | `name` | str | 앞뒤 공백 제거, 수식 접두 문자 방어 |
| F | 학번 | `student_id` | **str** (결정) | 샘플 셀은 숫자. 숫자면 정수→문자열. 정확히 8자리가 아니면 BLOCK(선행 0 소실 의심). 길이 규칙은 OPEN H2/M-항목 |
| G | 학과 | `department` | str | |
| H | 사업자등록번호 | `biz_no` | str(12) | 숫자 변환 금지 |
| I | 활동기관 | `org_name` | str | |
| J | 근로지 | `work_place` | str | |
| K | 멘토 인원 | `headcount` | int | 의미(멘토/멘티) [확정 필요] |
| L | 시급 | `hourly_rate` | int(원) | 정수 아니면 오류. float 금지 |
| M | 시간 | `minutes` (+ 진단용 원문) | int(분) (결정) | `#시간`, `#시간#분`만 허용, 그 외는 BLOCK. 출력 시 `N시간[M분]`로 변환 |

| **O** | 재단 장학금 계 | `pay_amount` | int(원) | **출력 지급액의 원천(결정: 재단 승인금액 기준)**. 다른 사업에서도 같은 열인지는 샘플 확보 후 확인 |

| Q | 이자수익 집행액 | `interest_amount` | int(원) | |
| R, S | 대응투자/추가금 | `univ_basic`, `univ_extra` | int(원) | 샘플 0. 출력에는 쓰지 않음, 0이 아니면 경고 [확정 필요] |
| T | 은행명 | `bank_name` | str | 은행코드 표의 `B`열과 정확 일치해야 함 |
| U | 계좌번호 | `account_no` | **str** | 하이픈 포함 그대로. 숫자 변환 금지 |

| 48행 | 합계 | `source_totals` | | 데이터 행에서 계산한 합과 대조 후 **버림** |

## 3. `PaymentBatch` → `WINS` (2행~, 행 r = 명단 행 r+3)

| 열 | 헤더 | 값 |
|---|---|---|
| A | 근로구분명 | 정책 상수 `<근로구분명 상수>` [샘플, 사업별 [확정 필요]] |
| B | 년도 | `year` 숫자 |
| C | 월 | `month` 숫자 |
| D | 학번 | `student_id` (명단 `D`와 동일 타입) |
| E | 근무부서코드 | 공란 [샘플] |
| F | 근무일수 | 공란 [샘플] |
| G | 재단 장학금 | `pay_amount` (값 기록) |
| H | 은행코드 | WINS 은행코드(은행코드 시트 `C`)를 **Python에서 변환한 값** |
| I | 계좌번호 | `account_no` (값 기록) |

**방향(우선 검토, 최종 확정 아님)**: 값 기록. 샘플의 수식 `=VLOOKUP(D2,'지급대상자명단(9월)'!$D$5:$L$100,9,0)` 등은 명단 `$100` 고정이라 최대 96명이고 시트명에 월이 들어 있어, 수식을 유지하려면 범위·시트명을 매번 재작성해야 한다. 업로드 호환성 검증(OPEN H1) 전까지 수식 병행 옵션을 닫지 않는다. 학번 셀 타입은 OPEN H2.

## 5. 은행코드 변환
- 키: 입력 `T`(은행명) 정확 일치 → `은행코드!B`. 불일치·공백·중복 후보는 **BLOCK**(추정·유사 매칭 금지).
- **결정**: 시스템별 개별 변환. WINS 코드 = `C`, WRIS 코드 = `D`. 지급 대상자의 필요한 코드가 없거나 모호하면 **지급명단 생성 차단**. (샘플 표에서 WINS 코드는 37/78 공란이므로 해당 은행 지급자가 있으면 생성 불가. 표 보완 절차는 OPEN M5.)
- 명단의 `N`/`O` 열을 값으로 쓸지 수식으로 둘지는 OPEN M4. 어느 쪽이든 Writer가 독립 계산한 코드와 일치해야 한다.
- 은행코드 표는 템플릿과 함께 배포하며 사용자가 임의로 수정하지 않는다.

## 6. 다문화·탈북학생 멘토링 / AI멘토링
샘플 미확보 → 열 매핑, 금액 원천, 사업 상수 모두 **미작성**. 사업별 `Adapter` 인터페이스(§IMPLEMENTATION-PLAN)만 정의하며 "완료"로 표시하지 않는다.
