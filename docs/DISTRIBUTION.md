# 배포와 Windows SmartScreen

Actions가 만드는 앱은 **코드 서명이 없다**(인증서 비용을 쓰지 않기로 함, 2026-11-04). 그래서 인터넷에서 받은 파일은 Windows 에서 "PC 보호 / 게시자를 알 수 없음" 화면이 뜰 수 있다. 서명 없이 이 경고가 **완전히 사라진다고 보장할 수 없다**. 아래는 완화 방법이다.

## 받는 사람(담당자)
1. 가능하면 브라우저로 직접 받지 말고 **학교 공유 폴더·USB 등으로 복사**해서 받는다(SmartScreen 은 인터넷에서 받은 표식이 붙은 파일을 검사한다).
2. 이미 받았다면 zip 을 풀기 **전에** 파일 속성 → "차단 해제"에 체크하고 적용한다. 또는 경고 창에서 "추가 정보 → 실행".
3. "실행" 버튼이 없으면 관리자 정책이 막은 것이다 → 아래 전산팀 요청.

## 전산팀 허용 요청에 첨부할 자료
- 저장소 주소(소스 공개)와 빌드한 Actions 실행 기록(소스 → 빌드 과정 확인 가능)
- 버전, `SHA256SUMS.txt`(앱 폴더 안): 해시 또는 폴더 경로로 허용 등록
- 네트워크를 쓰지 않는 오프라인 도구(코드에 네트워크 모듈 없음, 2026-11-04 검색으로 확인)
- 개인정보는 PC 안에서만 처리하고 외부로 보내지 않음

## 빌드 산출물 (이 저장소)
- 폴더 방식(onedir): 압축 해제용 임시 폴더를 쓰는 단일 exe 방식보다 백신 오탐이 적은 편이다.
- exe 파일 속성에 제품명·설명·버전이 들어간다(`packaging/make_version_info.py`, 버전은 `__version__` 하나만 사용).
- 화면의 기본 정책·템플릿 자동 채움은 **exe 가 있는 폴더**를 먼저 찾는다(`config/default_paths.py`). 폴더 방식에서도 같은 위치다.

## 운영 규칙
- SmartScreen 평판은 파일 해시별로 쌓이므로, 나눠 준 버전은 자주 바꾸지 않는다. 필요한 수정을 모아 버전을 올린다.
- 예산이 생기면 기관 명의 OV 코드 서명 인증서를 검토한다(EV 라도 즉시 신뢰는 아니다). 서명 단계는 빌드에 한 단계로 추가할 수 있다.
- 개인 명의 Microsoft 서명 서비스는 한국에서 쓸 수 없고, SignPath 무료는 OSI 오픈소스 라이선스가 필요해 현재 제외.

## 검증 상태
Windows 에서 실행 확인 **전**. 확인할 것: ① 브라우저 다운로드본 vs 공유 폴더 복사본의 SmartScreen 표시 ② 폴더 방식 실행·화면 제목 버전·기본 정책/템플릿 자동 채움 ③ 학교 PC Defender 오탐.
