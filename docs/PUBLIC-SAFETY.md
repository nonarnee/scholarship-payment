# 공개 저장소 안전 설계 (GitHub Public)

> 이 저장소는 **공개**로 운영한다. git 이력은 되돌리기 어렵고 포크·캐시·검색에 남을 수 있으므로, 실제 업무자료는 **처음부터 들어오지 못하게** 설계한다.
> 원칙: ① 실제 자료와 공개용 자료를 물리적으로 분리 ② 기본 차단(deny by default) ③ 사람이 아닌 도구가 커밋 전에 검사 ④ 문서에도 실값을 쓰지 않는다.

## 1. 데이터 분류

| 구분 | 예 | 저장소 |
|---|---|---|
| **공개 가능** | 코드, 설계 문서(구조·규칙·결정), 합성 템플릿·합성 테스트 엑셀, 안전 검사 도구 | 포함 |
| **비공개: 개인정보** | 학생 성명·학번·학과, 계좌번호, 지급금액 합계 등 실제 값 | 금지 |
| **비공개: 기관정보** | 학교·활동기관·근로지 이름, 사업자등록번호, 사업 담당자 정보 | 금지 |
| **비공개: 내부 시스템 식별값** | 외부 업로드 시스템의 구분코드·상수 값·고유 헤더명·내부 시트명, 계정·서버 정보 | 금지 |
| **비공개: 업무자료 파생물** | 실제 파일명(날짜 포함), 합계 값, 값의 종류 수·분포·형식 통계, 마스킹본 | 금지 |
| **불확실** | 마스킹 샘플 | **공개 안전성 미확인 → 금지** |

"구조·규칙"(시트 구성, 열 위치, 병합, 검증 규칙)은 공개한다. 그 구조에 **채워 넣는 값**은 공개하지 않는다.

## 2. 저장소 레이아웃

| 경로 | 성격 | git |
|---|---|---|
| `src/`, `tools/`, `tests/`, `docs/`, `templates/` | 공개 | 추적 |
| `templates/synthetic_*.xlsx`, `tests/fixtures/synthetic/synthetic_*.xlsx` | 완전 합성 엑셀(유일한 허용 xlsx) | 추적 |
| `samples/`, `private/`, `real/` | 실제·준실제 업무자료, 비공개 노트 | **무시** |
| `.safety/` | 로컬 금지어 목록(실값에서 생성) | **무시** |
| `output/`, `out/`, `tmp/`, `scratch/`, `diagnostics/` | 생성 결과·임시·진단 | **무시** |

`.gitignore`는 모든 데이터 확장자(`*.xlsx *.csv *.pdf *.hwp …`)를 차단하고, 위 합성 파일명만 예외로 연다.

## 3. 공개 문서·코드 작성 규칙
1. 실제 값 금지: 성명, 학번, 계좌, 사업자번호, 기관명, 금액 합계, 구분코드, 상수 문자열, 실제 파일명·기준일.
2. 외부 시스템 고유 문자열은 **중립 이름**으로 쓴다. 예: WRIS 영문 헤더 → `gub_a`, `gub_b`, `verify_no`, `payee_name` …, 구분코드 → `<구분코드A>`, 상수 → `<근로구분명 상수>`.
3. 통계 금지: "N종", "전부 …로 시작", 값 형식 분포 등 실자료에서 얻은 수치. 구조 수치(행 번호, 열 문자, 병합 개수, 시트 수)는 허용.
4. 실자료로 얻은 **사실**은 문서에 "관찰/검증 필요"로 적되 값은 적지 않는다. 필요한 실값 대응은 `private/` 노트에만 둔다.
5. 예시는 합성 예약값만 쓴다(§4).

## 4. 합성 데이터 규칙 (예약값)
| 필드 | 합성 규칙 | 검사기 허용 |
|---|---|---|
| 성명 | `가상NNN` | - |
| 기관·근로지·학과·은행 | `가상기관NN`, `가상근로지NN`, `가상학과NN`, `가상은행NN` | - |
| 학번 | `90NNNNNN`(숫자 셀 시험), `00NNNNNN`(문자열·선행 0 시험) | ✔ |
| 년월 | `9999NNNN`, 연도 `2099` | ✔ |
| 사업자번호 | `000-00-NNNNN` | ✔ |
| 계좌 | `000-000-NNNNNN` | ✔ |
| 시급·금액 | 시급 1000, 합계가 8자리 숫자가 되지 않도록 작게 | - |
| 상수·구분코드 | `SYN-*`, 중립 헤더(`gub_a` 등) | - |
| 은행코드표 | 합성 은행·합성 코드(공란·중복 이름 포함) | - |

모든 합성 엑셀은 문서 속성에 `SYNTHETIC-TEST-DATA` 표식을 넣고 작성자를 `synthetic-generator`로 한다. 생성기: `tools/synthetic/make_synthetic.py`(실제 파일을 **읽지 않는다**).
실제 원본과의 구조 충실도(시트·병합·숨김 열·셀 타입·빈 문자열 칸 등)는 `tools/synthetic/check_fidelity.py`로 **로컬에서만** 점검한다(값은 출력하지 않고 차이만 출력).
합성 템플릿은 실제 양식의 **레이아웃을 모사**한다(시트 구성, 병합, 열 너비, 행 높이, 수식 구조). 이 모사 수준이 공개 가능한지는 사용자가 최종 판단한다(OPEN-QUESTIONS H6).

## 5. 비공개 값은 설정으로 주입한다 (설계)
- 코드(공개)는 실제 헤더·상수·구분코드·적요 형식·템플릿을 **갖지 않는다.** `BusinessOutputPolicy`와 헤더 지문은 **외부 설정 파일**에서 읽는다.
- 저장소에는 합성 기본 설정(`SYN-*`)만 둔다. 실제 설정과 실제 템플릿은 학교 PC에 별도 배포(저장소 밖, 또는 `private/`)한다.
- **빌드 산출물 규칙**: 공개 릴리스·GitHub Actions 아티팩트에는 합성 템플릿만 포함한다. 학교용 번들(실제 설정·템플릿 포함)은 비공개 경로에서 로컬로 만든다.

## 6. 검사 체계 (3중 방어)
| 단계 | 방법 | 비고 |
|---|---|---|
| 1. 차단 | `.gitignore` 기본 차단 | `git add`가 무시. `git add -f`는 막지 못함 |
| 2. 커밋 전 | `tools/safety/hooks/pre-commit` → `check_public_safety.py --staged` | 설치: `sh tools/safety/install-hooks.sh`. `--no-verify`로 우회 가능 |
| 3. 푸시 전 | 수동 `check_public_safety.py --tracked`(인덱스) / `--worktree`(작업트리) | **푸시 전 필수.** 훅 우회 방어 |
| 4. 계획 | GitHub Actions에서 PR마다 같은 검사 실행 | 아직 미구현(Actions 단계에서 추가) |

검사 규칙: P1 경로·확장자, P2 엑셀 이름, X1 엑셀 속성(표식·작성자), X2 엑셀 구조(외부 링크·매크로·숨김 시트), T1 패턴(사업자번호·계좌·주민번호·전화·이메일·8자리 숫자), T2 **로컬 금지어**.
출력에는 일치한 값을 표시하지 않고 규칙 ID·파일·줄·길이만 낸다.

### 로컬 금지어(T2)
- `tools/safety/build_denylist.py <비공개 xlsx…>`가 실제 자료의 값(이름, 기관명, 학과, 번호, 상수, 금액 후보)을 `.safety/denylist.local.txt`에 모은다(git 무시).
- 합성 파일의 라벨과 `tools/safety/public_terms.txt`(공개 용어)는 제외해 오탐을 줄인다.
- 새 실자료를 받을 때마다 다시 실행한다. **이 파일이 없는 PC에서는 T2가 동작하지 않는다**(경고 출력).

## 7. 커밋·푸시 절차
1. 새 파일이 데이터 파일이면 §1 분류를 먼저 확인한다. 합성 엑셀은 생성기로만 만든다.
2. `python3 -I tools/safety/check_public_safety.py --worktree` 통과 확인.
3. `git add` 후 `git diff --cached`를 눈으로 훑는다(검사기는 이름·기관명을 사전 없이는 알 수 없다).
4. 커밋(훅이 자동 검사).
5. 푸시 전 `--tracked` 재실행, 원격이 의도한 저장소인지 확인.
6. 최초 푸시 전에는 **로컬 이력 전체**에 실값이 없는지 확인한다(아래 §9).

## 8. 한계
- 이름·기관명 같은 **자연어 값**은 로컬 금지어에 있어야만 잡힌다. 사전에 없는 값은 사람이 검토해야 한다.
- 합성 템플릿이 실제 양식의 구조를 모사하는 것 자체가 공개 가능한지는 정책 판단이다.
- 마스킹본은 검사로 안전을 증명할 수 없다. 공개 안전성이 확인되기 전에는 저장소에 두지 않는다.

## 9. 현재 상태와 조치 필요 사항
- 작업트리: `--worktree` 검사 통과(문서·스크립트에서 실값 제거, 합성 파일 생성).
- **로컬 커밋 `42dd48d`에는 정리 전 문서가 들어 있다**(구분코드, 합계 값, 샘플 파일명, 값 종류 수 등). 아직 푸시하지 않았다. 푸시 전에 이력을 정리해야 한다(예: 정리 후 단일 새 루트 커밋으로 재작성 — 로컬 전용이므로 위험이 낮지만 **사용자 승인 후** 진행).
- 원격은 비어 있는 public 저장소다. 이력 정리 전에는 푸시하지 않는다.

## 10. 유출 대응
1. 즉시 저장소를 private으로 전환한다.
2. 해당 커밋을 이력에서 제거(force push)하되, 포크·캐시·검색 노출은 막지 못할 수 있음을 전제로 한다.
3. 영향받는 정보 범위를 파악하고 학교 개인정보 담당 부서에 보고한다.
4. 재발 방지: 금지어·검사 규칙에 원인 패턴을 추가한다.
